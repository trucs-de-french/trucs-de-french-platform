## Що вже працює

- `src/lib/delf/evaluation-grids.ts` — офіційна сітка FEI (реформа 2023):
  5 критеріїв (Réalisation de la tâche, Cohérence et cohésion, Adéquation
  sociolinguistique, Lexique, Morphosyntaxe), 4-рівневі дескриптори
  (below/atTarget/above + "zero"), шкали балів по рівнях, пороги довжини
  тексту, правила аномалій (copie blanche, недостатній обсяг, hors-sujet

  не довіряються AI.
- `src/lib/delf/check-answer.ts` — `checkEssayAnswer()` (5-критерійна
  оцінка + помилки з поясненнями + поради) і `checkFormulaireAnswer()`
  (A1 Exercice 1 — формуляр, окрема проста фактологічна перевірка).
- `src/lib/exercises/types.ts` — `EssayCheckConfig` (level, exerciseNumber),
  `EssayFormulaireConfig`.
- `src/app/api/delf/check/route.ts` — розгалуження formulaire/есе,
  нормалізація балу для `recordTaskAttempt`.
- Адмінка: `task-config-fields.tsx` + `essay-formulaire-fields.tsx` —
  вибір рівня/вправи, редактор полів формуляра.
- Студентський UI: `essay-check.tsx` — підсвічені помилки в тексті
  (клік → виправлення/категорія/правило/пояснення), розбір за 5 критеріями,

## Рішення, прийняті по дорозі (не з явної специфікації)

- **A2 Ex.1/Ex.2 — окремі task-записи** (по одному на вправу, з полем
  `exerciseNumber`), а не один запис з двома текстовими полями. Узгоджено
  з користувачем явно.
- **Показ балу студенту — лише офіційна шкала /25 (або /15 для A1)**, без
  перерахунку у відсотки на екрані. Узгоджено з користувачем явно.
  Внутрішньо (`recordTaskAttempt`) бал усе одно нормалізується в 0–100 —
  лише для агрегації прогресу, студент цього не бачить.
- **A1 Ex.1 (формуляр) — той самий підхід "одна вправа = один task-запис"**,
  що й A2, для консистентності (не було explicit підтверджено, але випливає
  з логіки A2-рішення).
- **Поріг "correct" для progress/mistakes — 50% від maxScore завдання**
  (НЕ офіційний прохідний бал DELF-сертифікації — той рахується по
  сукупності 4 навичок інакше). Суто внутрішній поріг платформи.

## Зв'язок з новою структурою треків (DELF entraînement/examen)

Ця інфраструктура (`essay_check` + `evaluation-grids.ts`) — це і є PE
(Production Écrite) для нового треку "DELF". У режимі **Entraînement**
працює як є (миттєвий фідбек після відправки). У режимі **Examen**
знадобиться зміна поведінки: результат перевірки не показується одразу
після відправки секції PE, а ховається до завершення всього іспиту —
це стосується Етапу 3 структурної зміни (див. окрему розмову/план), сама
логіка оцінювання (`checkEssayAnswer`) не зміниться, зміниться лише коли
її результат показують студенту.
